# Delete-swipe calibration and editor compatibility — 16 October 2026

This update retains the previously published learned punctuation, observed casing, Fn formatting, theme rotation and bounded suggestion search. It publishes the final tested Plektra sources corresponding to the local test APK version 102, including the subsequent restoration of separate suggestion-space insertion. It does not rebase onto a later upstream release.

## Independent calibration for leftward word deletion

The trackpad gestures screen now includes **Calibrate delete swipe**, separate from the existing suggestion-acceptance calibration. Record five comfortable right-to-left swipes from the intended thumb position, then save. Calibration adapts the normalized horizontal starting region, movement distance and speed; it does not record a separate vertical starting band. Users can restart, cancel or restore the default gesture.

Calibration gestures do not delete words or accept suggestions, including the old firmware delete-key path. Leaving the calibration screen stops capture. Saving enables native-IME swipe deletion without replacing the independent suggestion calibration. The saved profile is included in the settings backup; transient samples remain in a separate session store. The existing native touchpad/device/API requirements still apply. New labels and messages are included in all eleven supported languages.

## Temporary spaces, punctuation and suggestion acceptance

Unicode ellipsis `…` is handled as closing punctuation, including alternate-character input. Separate dots are covered by regression cases with optional after-punctuation spacing enabled. French nonbreaking spacing is retained.

Closing bold or italic now moves verified automatic spaces generated by punctuation as well as suggestions outside the closing marker. For example, `*tu vois ? ` becomes `*tu vois ?* `, and `_bonjour ! ` becomes `_bonjour !_ `. The narrow nonbreaking space before the sign stays inside. Automatic comma spacing is tracked too. Manual spaces and another input connection's provisional space are not trimmed.

Tap and swipe acceptance share one insertion helper. The final implementation restores the legacy primary sequence: commit the replacement word, then commit its space separately, without an additional caller-owned batch. The primary space is sent even when surrounding text is unavailable. A readable suffix must confirm a missing separator before native-space or atomic-replacement compatibility fallbacks are attempted. Only verified spaces are registered for later formatting cleanup.

An existing ASCII space following the replaced token is moved before the caret, while newline, tab and nonbreaking characters are not consumed. A paragraph boundary after the caret no longer suppresses the provisional separator before it. Continuations ending in an apostrophe still receive no added space.

An earlier attempt to send word and space together, followed by a paragraph-boundary-only change, failed to resolve the user's Outlook/Docs symptom. Those attempts are superseded by the final separate-space sequence; they are not described as successful app fixes. The user subsequently reported success with the final supplied build. Compatibility tests use simulated editors, including one that distinguishes a word commit from a standalone separator; they do not establish the exact internals of Outlook or Google Docs.

## Smart quotes and Telegram

Smart-quote conversion recognizes a complete English curly pair `“…”` as well as straight quotes. This covers the form the user observed in Google Docs. Conversion still waits for the next supported delimiter after the closing quote and respects disabled/restricted contexts. Configured French guillemets and narrow nonbreaking spaces are retained; missing opening context is not guessed.

Telegram profiles use `**` for bold and `__` for italic, including the official Android variants and Telegram X. Underline remains unavailable in marker-based profiles. French Fn+G/I/S and other input languages' Fn+B/I/U remain unchanged, as do native rich-editor shortcuts, WhatsApp markers and optional Reddit Markdown. Telegram marker edits notify the same context/learning path as the other messaging profiles.

## Configured sending and real-device feedback

The explicit editor-action send strategy requests Send rather than accepting an unrelated Done, Next or Search action. A custom action identifier is preserved only when the editor advertises Send. An explicit rejection produces a translated message. Synthetic Ctrl+Enter and plain-Enter events use Android uptime timestamps. There is no automatic cascade of send attempts after a potentially successful action.

ChatGPT and Reddit appear in the existing per-app configuration. They are not relabeled as universally tested applications. User phone feedback confirms Alt+Enter sending in ChatGPT and Reddit private chat, while sending from a Reddit post comment remains unresolved. The user chose to leave that limitation for now. The new delete-swipe calibration was also confirmed working on the phone.
